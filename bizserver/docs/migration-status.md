# Rust 后端迁移状态

本轮把后端迁移入口放入 `Boji/bizserver/`。旧目录仍是只读参考。没有复制旧数据库、密钥、邮件或测试凭据。

| 层 | 当前实现 |

| 数据访问 | SeaORM 2.0.4 |

| 工具链 | Rust 1.99.0 |

认证依赖固定在 `9f91cd7fdb8a5f73a9c69d5c56d363468a7dc281`。依赖仍处于 alpha 阶段。`Cargo.lock` 固定完整依赖图。升级前必须重跑认证与协议测试。

## 旧数据保护

迁移命令只初始化新的 PostgreSQL 数据库。如果发现未登记的旧认证表，命令会停止。新服务不对旧 Drizzle 数据库直接执行建表迁移。

生产切换前需要完成以下步骤：

1. 在脱敏副本中实现数据转换与核对。
2. 验证密码策略和会话迁移策略。
3. 完成未迁入功能与安全控制。
4. 让原生客户端通过 ConnectRPC 联调。
5. 演练备份恢复，再确定停写与切换窗口。

当前程序拒绝以 `APP_ENV=production` 启动。移除保护前必须完成上述验收。Docker 配置仅用于独立开发环境。

服务启动前会只读检查迁移版本。旧库、未初始化的库和版本不符的库都会被拒绝。启动检查不会自行创建迁移登记表。
