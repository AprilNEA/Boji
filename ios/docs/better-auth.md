# Better Auth 原生接入

iOS 使用原生 Swift 调用 Better Auth HTTP 接口。后端负责密码校验、会话签发和撤销，客户端不另建认证系统。

现有网络实现已使用 Better Auth 的 Bearer 协议。[1] 官方客户端说明主要面向 JavaScript 框架。[2] 已查到的 Swift SDK 为独立社区项目，不由 Better Auth 团队维护。[3] 本轮保留原生网络栈，不额外引入该依赖。

## 客户端分层

- `BetterAuthClient`：注册、登录、验证邮件、找回密码和会话管理。
- `BojiHTTPClient`：统一 HTTP 请求、Bearer 头和服务端错误。
- `MembershipAPI`：会员接口，以及兼容现有调用的认证转发。
- `MembershipStore`：界面状态、Keychain 令牌和独立会员缓存。

注册、邮箱登录和 Apple 登录仍使用后端已有接口。注册成功不自动登录，需要先验证邮箱。邮箱验证和找回密码继续通过后端网页完成，不把普通导航链接当作认证回调。

## 账号与安全

登录后，入口为「设置 → 账号与安全」。新增功能使用 Better Auth 自带的端点。[4] [5]

- 当前会话：`GET /api/auth/get-session`。
- 修改密码：`POST /api/auth/change-password`。
- 退出其他会话：`POST /api/auth/revoke-other-sessions`。
- 更换邮箱：`POST /api/auth/change-email`。
- 删除账号：两次调用 `POST /api/auth/delete-user`。

会话页显示登录时间与到期时间。客户端不保存服务端响应中的原始会话 token、IP 或设备代理字段。空会话响应表示认证失效，不能作为有效登录。

修改密码前，界面要求输入当前密码并确认新密码。最终确认会提示其他会话将退出。客户端明确发送 `revokeOtherSessions: true`，不自动重试写请求。

改密后的认证令牌只从 `set-auth-token` 响应头读取。客户端不会回退使用正文中的原始 token。如果服务端已确认改密，但没有提供签名令牌，客户端要求重新登录。

错误提示区分密码错误、会话失效和请求过于频繁。网络中断时，修改结果可能不确定，界面不会声称密码一定没有变化。

## 更换邮箱

入口为「设置 → 账号与安全 → 更换登录邮箱」。只有邮箱已验证的账号可以使用。客户端先检查新邮箱的格式，并拒绝与当前邮箱相同的地址，然后发送 `{"newEmail":"<新邮箱>"}`。服务器的三步流程见[后端契约](../../bizserver/docs/migration-auth.md#注销账号与更换邮箱)。

服务器接受请求后，页面显示「待生效的新邮箱」。用户先打开旧邮箱中的确认链接，再打开新邮箱中的验证链接。在此之前，账号仍用旧邮箱登录。新邮箱已属于其他账号时，服务器同样返回成功，但不发送邮件，所以提示文字只说「如果新邮箱可以使用」。

待生效的新邮箱只保存在内存中。App 回到前台时，如果有待生效的更换，页面会刷新会话。会话显示新邮箱后，页面清除这个状态。退出登录也会清除它。

## 删除账号

入口为「设置 → 账号与安全 → 删除账号」。会员页的「账号安全」也通向此页。

1. 用户点击「发送注销确认邮件」。客户端发送 `{}`，要求服务器向账号邮箱发送确认码。
2. 用户输入邮件中的完整确认码。确认码是不透明字符串，不限于数字。
3. 用户点击「删除账号」，再确认「永久删除账号」。客户端发送 `{"token":"<确认码>"}`。
4. 服务器确认删除后，客户端清理登录令牌和会员缓存。服务器账号、会员卡和关联数据按[后端契约](../../bizserver/docs/migration-auth.md#注销账号与更换邮箱)删除。

两次请求都使用签名 Bearer 会话。客户端不自动重试，不把发码成功当作删除成功。取消、退出或切换账号会使本机待确认状态失效。确认码只在内存中使用，不写入日志、缓存或导出文件。

删除账号不会清除本机训练、饮水、睡眠和身体记录。删除本机记录仍是设置中的独立操作。已添加的 Wallet 卡片需要用户自行移除。

服务端目前不撤销 Apple 的第三方令牌。因此，完成此界面不代表 Apple 登录账号的注销已通过上架验收。发布前还须补齐并验证该服务端流程。

## 安全边界

令牌只保存在 Keychain。网络层关闭 Cookie 自动保存，并阻止 HTTP 重定向。密码只在输入和请求期间使用，不写入日志、偏好设置、共享容器或会员缓存。

普通启动使用真实网络。仅 Debug 的 `--uitesting` 启用隔离测试服务。

邮箱变更尚未接入。活动记录同步与本轮认证接入无关，仍默认不上传数据。账号注销的正式邮件与真实 HTTP 往返仍须独立验收。

## 服务配置

`BOJI_API_BASE_URL` 必须配置为后端服务基础地址，而不是登录页面。Debug 未配置时仍连接 `http://localhost:3000`。Release 必须显式提供 HTTPS 地址。

在真机上，localhost 指向手机自身。仅打开 Better Auth 客户端代码，不能代替部署服务或配置地址。Apple 登录还需要服务端启用对应能力。

本轮没有修改生产地址、读取 Apple 私钥或部署后端。也没有迁移共享测试数据库。

本轮使用 Xcode 27.1（27A9275）。测试设备为 iPhone 17 Pro Max 模拟器，系统为 iOS 26.5。应用版本为 `1.0 (7)`。时间为 2026-10-22（UTC+08:00）。所有账号、令牌与记录均来自隔离测试数据。

- 145 项单元测试通过，其中包含 12 项注销测试。
- 3 项注销界面测试分别通过：取消、二次确认后删除、服务器拒绝。
- 成功删除后，界面回到未登录状态，原有 `250mL` 饮水记录保留。
- 深色模式与最大辅助功能字号下，发码、空码禁止提交和取消后重新进入通过。
- 已查看确认弹窗、删除成功、服务器拒绝及大字体截图。大字体内容可滚动，未缩小用户设置的字号。
- Debug 与 Release 模拟器构建通过。Release 包不含 Debug 测试目录。

最初的界面回归暴露了测试定位和测试数据问题。系统弹窗包含重复按钮节点，断言未滚动到大字体按钮。错误测试数据还曾在发码阶段拒绝请求。这些问题均已修正后复测。三项界面结果来自两次复测，不表示本轮重跑了全部既有 UI 测试。

删除响应无效、网络中断或服务器返回 5xx 时，客户端保留账号状态，但清除待确认状态。界面提示结果未确认，不允许直接重放同一待确认请求。客户端不会把未确认结果说成删除成功。

未验证：正式邮件与真实 HTTP 注销、真机 Keychain、Apple 第三方令牌撤销、GitHub 托管 Runner 上的本次修复。测试成功不能代替这些发布验收。

测试结果包在隔离工作区的 `.work/boji-ios/release-readiness/`：`DeletionTests-retry.xcresult` 与 `DeletionLargeText.xcresult`。任务日志和导出截图在主工作区的 `.work/boji-release-20261022/`。本轮没有使用生产账号、上传 IPA 或提交审核。
